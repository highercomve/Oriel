Why Oriel

Everything a desktop app needs, compiled in only when you ask for it.

Small and fast to build

A release app is a few MB. The build cache is hundreds of MB, not gigabytes, and Zig rebuilds incrementally.

Typed both ways

Write Commands and Events as plain Zig structs. invoke and listen are generated for TypeScript at compile time.

Secure by default

Navigation limits, per-origin command capabilities, a strict CSP, and a bridge injected only into your own pages.

Batteries, opt-in

Tray, updater, SQLite and sqlite-vec, dialogs, notifications, global shortcuts, clipboard, file watching, deep links, audio capture, media server.

Local AI built in

llama.cpp and whisper.cpp as modules: CUDA, Vulkan and Metal on the desktop, Metal on iOS, and ARM dotprod/i8mm CPU kernels, Vulkan, OpenCL and Hexagon on Android.

Voice, tuned

oriel.dictation: live dictation and file transcription out of the box. Whisper with voice detection, live draft text and a measured CPU or GPU per device, or the phone's own recognizer.

Chat, tuned

oriel.chat is a local LLM in a module: models, the chat template, streamed tokens and a reused KV cache, on the CPU or the GPU, per device.

Phones and tablets too

The same app on Android (phones, desktop mode, ChromeOS) and iOS. Tiles, a keyboard, notification actions and deep links stand in for the tray and hotkeys.

Ship it

oriel package builds deb, rpm, AppImage, .dmg and Windows setup.exe (natively or cross-compiled from Linux); oriel android build an APK and AAB; oriel ios build an .ipa.

In this release

Oriel 0.8.0 · October 4, 2026. The native UI renderer is available as an experimental, opt-in build mode.

Your frontend, drawn natively

-Dnative_ui runs the same HTML, CSS and JavaScript with QuickJS, a DOM written in Zig and platform drawing on Linux, Windows, macOS, Android and iOS. React, Vue, Svelte, Preact and CSS-in-JS apps run on it.

Text and controls that fit

Mixed-font lines, baseline alignment, decorated inline text and styled SVGs. Android text widths and control sizes follow its WebView; macOS buttons keep their default AppKit appearance until styled.

Canvas from JavaScript or Zig

Breakout runs either way, in both renderers. Numeric canvas recording and transform updates reduce work per frame; the render bench covers rows, animation, canvas and memory on Android and desktop. Battery savings have not been established.

The showcase

examples/showcase: every Oriel feature in one app, from one codebase, for Linux, Windows, macOS, Android and iOS. Below, on a Pixel phone.

smoke

examples/smoke: every module gets a pass/fail check inside a real webview — one run tells you Oriel works end to end on your machine, not just that it compiles.

  • Tray & menus — dbusmenu icons, layout and actions
  • Updater — Ed25519-verified manifests, tampered copies rejected
  • Data — SQLite (with sqlite-vec), the JSON store, fs watching
  • Desktop — dialogs, notifications, global shortcuts, clipboard, typed input into other apps
  • Webview & IPC — page fetch, invoke round trips, async commands from worker threads

It runs in CI on every platform with each check listed, so a red one names the module.

breakout

examples/breakout: a canvas game with an HTML and CSS interface, in the WebView or the native renderer. Drag on a phone; mouse or arrow keys on the desktop.

  • Three ways — the physics and drawing in JavaScript, or in Zig through oriel.canvas
  • 500 balls on a 120 Hz phone — 120 fps from Zig (0.35 ms a frame), 63 fps from JavaScript, 120 in the WebView
  • 500 balls on a 144 Hz laptop — 144 fps from Zig, 59–75 from JavaScript, 103–116 in the WebView

Verified

Android

Verified

iOS

UIKit + WKWebView from Zig, no Xcode project. .app and .ipa, Metal for whisper / llama. The showcase verified in the iPhone simulator (iOS 18): commands, events, workers, local chat, a second window. Real devices next.
